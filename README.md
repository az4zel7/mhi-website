# Milton Hosiery Industries — website

Next.js (App Router) build of the MHI website: Home, About, Products (with
brand tabs, real ANICY photos, hover-cycling and a full-screen carousel),
Contact. Available in **English, Hindi and Marathi** with browser-language
auto-detection and a manual switcher in the nav.


## Setup: enquiry emails, WhatsApp and contact details (Phase 0)

**Contact details** live in one file: `lib/site.js` (phone, WhatsApp number, public
email, address). Before launch:

- Confirm `whatsapp` is the number you want customers to message (it currently
  matches the phone number).
- Add a real `email` — until you do, no email row is shown on the Contact page.

**Enquiry form.** Submissions are emailed through [Resend](https://resend.com) by
`app/api/contact/route.js`. Copy `.env.example` to `.env.local` and set:

| Variable | Purpose |
|---|---|
| `RESEND_API_KEY` | Your Resend API key |
| `CONTACT_TO_EMAIL` | Who receives enquiries (comma-separate for several people) |
| `CONTACT_FROM_EMAIL` | Optional. Needs a domain verified in Resend; until then Resend's test sender only delivers to your own Resend sign-up email |

Set the same variables in your hosting dashboard for production. If they are
missing, the form shows an error and offers WhatsApp instead — it never reports
success for an enquiry that wasn't sent. The form also has a hidden spam trap
field; it has no rate limiting yet.

**Before launch, send yourself a test enquiry from the live site.**

## Design system (Phase 1)

All styling is in `app/globals.css`, organised in numbered sections with a header
comment explaining the idea ("the trade catalogue"). Key points:

- **Tokens** live at the top (`:root`). MHI blue `#003B89` comes from the logo;
  kraft (`#C9A36B`) is the carton accent. **Red is reserved for NICY only.**
- **Fonts** (loaded in `app/[locale]/layout.js`): Archivo (headlines, with its width
  axis for the condensed look), Khand (Devanagari headlines — it sits after Archivo in
  the font stack so Hindi/Marathi get a matching face), Hind (body, Latin +
  Devanagari) and IBM Plex Mono (codes, labels).
- **Shapes:** square corners, no gradients or soft shadows. Reusable pieces:
  `.tag` (hang-tag label), `.bars`, `.stitch`, `.shade-strip`/`.shade-chip`, and
  the hard offset shadow used on hover/dropdowns/panels.
- **Hindi/Marathi:** section 13 switches off letter-spacing and uppercase (they break
  Devanagari) through the `--label-ls` / `--label-tt` tokens. Don't add tracking or
  `text-transform` directly to new components — use those tokens.
- **Logos** in `public/logos/` were trimmed of empty margins so they can be shown at
  a proper size. The untouched originals are in `public/logos/original/`.
- Contrast was checked for every text/background pair in the palette (all ≥ 4.5:1).

## Home page (Phase 2)

- **Hero photos** are set in `PLATES` at the top of `app/[locale]/page.js`; the
  photos beside each brand are `THUMBS`. NICY photos have a logo and design number
  printed into the top of the image, so those entries are zoomed in (`zs`/`zo`) to
  crop them out. Swap a photo by changing its path — check the crop afterwards.
- **Item codes** (e.g. `AN-03`, `NC-14`) come from `itemCode()` in `lib/brands.js`,
  generated from each product's position in its brand's list (designs are first grouped by collection, so each catalogue chapter is numbered consecutively). They are *not* real
  design numbers. If you have real ones, add a `code` field to the product and it
  takes priority. Don't reorder products without checking, as codes will shift.
- **The numbers strip** is `home.ledger` in each dictionary file. Every figure there
  is a public claim: 1973, 8,500 pieces/day, 5-day delivery, no MOQ on standard
  products, 600-piece private-label minimum. They come from the About page copy;
  confirm they are current before launch.
- **"How an order works"** is `home.slipSteps`. It describes the flow implied by
  the existing site copy (enquire → rates → delivery within 5 days) — edit it to
  match how you actually take orders.
- The old home text claiming "we don't operate our own factory floor" was removed.
  The home page now makes no claim either way about who manufactures.

## Catalogue (Phase 3)

**URLs.** `/products` lists the brands; `/products/anicy` (or `nicy`, `avron`) is a
brand's catalogue; `/products/nicy/v-crush-plazo` is one design. Old
`/products?brand=nicy` links redirect to the new URLs. Each design has its own link
you can send on WhatsApp.

**Adding or editing a design** — edit `lib/brands.js`:
- The URL slug is generated from the photo folder name (NICY) or the English name
  (ANICY). The build fails if two designs in a brand would get the same slug.
- Item codes (`AN-03`, `NC-14`) are generated by position, with designs first
  grouped by collection. **Inserting or reordering designs renumbers the codes after
  them.** If codes are printed anywhere (catalogues, labels), give each design a fixed
  `code` (and `slug`) field so they never move.
- NICY designs show a numbered shade card from their `colors`, and are grouped
  into chapters by `collection`. ANICY has no colour or collection data yet; add
  `colors` / `collection` to its designs and those parts appear automatically.
- Prices (`price` on NICY girls' wear) exist in the data but are deliberately **not**
  shown. Quote them on enquiry, as before.

**Enquiry list.** Buyers add designs with "Add to enquiry list", set optional
quantities, then send everything as one WhatsApp message (with a link to each
design) or through the contact form, which arrives pre-filled. The list is stored only
in the visitor's own browser (`localStorage`); nothing is saved on a server. Code:
`components/EnquiryProvider.jsx` (state and the message text) and
`components/EnquiryUI.jsx` (bar and drawer).

**Brand rooms.** Each brand header takes its shape from its logo: ANICY's diagonal
wedge, NICY's red swoosh, Avron's chrome. Styles are in section 8 of `globals.css`.

## Running it

```bash
npm install
npm run dev
```

Then open http://localhost:3000 — it will redirect to `/en`, `/hi` or `/mr`
based on your browser's language, or a saved preference. Requires internet
access on first run so Next.js can fetch the Poppins and Inter fonts from
Google Fonts.

```bash
npm run build   # production build
npm run start   # run the production build locally
```

Everything is plain text in those files — no code knowledge needed to edit,

**What stayed in English on purpose:** brand names (Milton, ANICY, NICY,
Avron), the company name, phone/email placeholders, and numbers/times.

## How language switching works

- `proxy.js` runs before every page request. If the URL doesn't already
  start with `/en`, `/hi` or `/mr`, it picks a locale (saved cookie first,
  then the browser's `Accept-Language` header, then English) and redirects.
- Clicking EN / हि / मर in the nav saves that choice in a cookie
  (`NEXT_LOCALE`) so it's remembered on the next visit, and takes you to the
  same page in the new language.
- Adding a fourth language later means: add it to `lib/i18n/config.js`, add
  a `dictionaries/xx.json` file, and add its translations to `lib/brands.js`.

## Editing brands, products and copy

`lib/brands.js` is the single source of truth for all four brands — name,
logo, accent color, segment, status, description, and product list. Text
fields are objects like `{ en: "...", hi: "...", mr: "..." }`; update all
three when you change something.

## Adding photos for a new product (matching the ANICY pattern)

1. Drop the images in `public/products/<brand>/<number>/1.jpg`, `2.jpg`, etc.
   (numbered in the order you want them to appear/cycle).
2. In `lib/brands.js`, add an `images: [...]` array of those paths to that
   product's entry.
3. That's it — the hover-cycle thumbnail and the click-to-open carousel both
   pick it up automatically. Products without an `images` array keep showing
   the simple garment-icon placeholder.
